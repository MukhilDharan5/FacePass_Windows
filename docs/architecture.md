# Architecture

The installed service uses LocalService, a service SID and protected Program Files/ProgramData ACLs. The per-user demo uses a separate pipe/store and never grants unlock authorization. Protocol v5 authenticates caller tokens and executable roles, verifies the running SCM service PID and bounds message sizes/nonces/I/O deadlines. The optional Microsoft-account password record is DPAPI-encrypted and SID-bound; its owned copies erase their secret on destruction.

Enrollment requires fresh interactive OS authentication. Capture/inference runs in FacePassCapture with explicitly inherited unnamed mapping, mutex and event handles. Its job object terminates it on parent exit. The supervisor cancels or kills blocked capture at a hard deadline. No public capture-helper success message can authorize a match.

Camera capture tries the configured Media Foundation device, then its path-matched DirectShow device for physical cameras. Open/read failures refresh the device list and try native Windows virtual cameras (including connected phones) through Media Foundation. Native virtual cameras are identified by the Windows device-interface property or the Windows Virtual Camera name suffix; unrelated physical and legacy third-party virtual cameras are not automatic candidates. Attempts are finite and retain the supervisor's overall deadline. Every replacement stream changes a camera generation; recognition challenges and enrollment samples reset on that change. No saved camera index, identity, permissions or activation policy is changed by failover. Phone availability in the installed service's Session 0 context still requires live validation.

Worker output carries bounded results/progress and optional 320x240 JPEG preview. Images are never persisted. Only ordinary own-account clients receive previews; provider/authority clients receive none. The parent serializes enrollment commit with Off/cancellation to prevent late saves.

YuNet receives an aspect-preserving frame capped at a 480-pixel shorter edge and 960-pixel longer edge. Its boxes and landmarks are mapped back to the original frame for quality checks and SFace alignment. Dim detector images, face quality regions, and aligned recognition crops receive adaptive gamma correction and blended CLAHE on Lab luminance; normally lit images retain their pixels. Raw face brightness and contrast must still contain usable signal before enhanced sharpness is assessed. Black/flat frames, blur, glare and multiple detected faces fail closed. This preprocessing is shared by enrollment and recognition and does not change match thresholds or liveness policy.

Recognition and enrollment consume camera frames without artificial retry sleeps. Recognition returns a successful result before generating an optional preview; worker previews are limited to 10 Hz. The provider polls active capture/approval status at 50 ms and idle automatic status at 200 ms. Camera/worker startup and Windows credential submission remain outside the inference latency.

Eligible LogonUI jobs use Strict liveness unless the user has explicitly saved the Instant profile. Instant accepts the first quality 2D face match at the configured threshold, with no liveness, minimum duration or multi-frame gate. Both paths can produce ten-second one-use service authorization. In password-backed mode only LogonUI in the matching locked console session can consume the grant to obtain the saved credential. The provider protects and packs it in its own logon session and targets built-in Negotiate. Windows authenticates the password; no FacePass LSA package is used. In the optional legacy mode the provider serializes a ticket to FacePassUnlock, whose package validates the existing locked local console session and returns copied native token information. Configuration changes cancel an active scan and revoke existing grants.

Off revokes/cancels. Manual requires selection or explicit diagnostics. Automatic starts one bounded service scan per eligible console lock/resume and LogonUI observes it independently of tile selection. Authenticated provider status polling closes the lock/Advise ordering race and retries activation if a previous camera job was still stopping. A live approval waits for a later session input event while the provider's Winlogon desktop receives input. Until both conditions hold, provider enumeration, tile selection and serialization cannot request sign-in or return a credential. Only then does CredentialsChanged request an auto-logon default; Windows controls final submission. Input timestamps are checked against the arming time/current uptime, including DWORD wrap; failed queries, inactive desktops, new nonces, expiry and cancellation require fresh confirmation. Provider teardown, leaving a selected face tile, unlock/desktop return, disconnect/logoff and suspend cancel/revoke. Resume queries the OS lock flag and retains only previously observed native-session provenance. Startup and disconnected sessions still require native authentication. See [automatic behavior and limitations](automatic-unlock.md).

Tests do not load a package into LSASS. LogonUI behavior, package/token/profile semantics and Session 0 camera availability remain VM validation requirements.
